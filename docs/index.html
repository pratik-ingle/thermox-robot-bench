Can a thermodynamic chip help a robot?

Seventeen linear systems, from a pick-and-place robot's Kalman gain to 256×256 random matrices. Each one is solved digitally (Exact, CG), on an emulated thermodynamic chip (plain thermox), and on the same chip inside iterative refinement (IR cold, IR warm).

Emulator: thermox 0.0.3 (Ornstein–Uhlenbeck sampler) · robot: Franka Panda in MuJoCo · accuracy target: 1e-4 relative error unless stated

Code, data and scripts: pratik-ingle/thermox-robot-bench
  • Exact: digital Cholesky solve, the reference answer
  • CG: digital conjugate gradient, the standard iterative method
  • Plain thermox: one chip run of N samples, averaged
  • IR cold: the chip inside iterative refinement, starting from zero
  • IR warm: the same, starting from the previous answer

Findings

  1. Iterative refinement fixes the chip's accuracy problem on 16 of 17 problems.To reach 1e-4, plain thermox would need 10⁸–10¹² samples. IR needs 40–33,000.
  2. Chip time tracks the condition number κ, not the matrix size.IR needs about 200 samples at κ = 10 and 17,000 at κ = 1000, at d = 16 and d = 256 alike.
  3. For robot-sized problems, the CPU wins.Kalman gains, arm IK and a 70-variable MPC take 0.3–10 µs on one CPU core. An optimistic future chip needs 4–330 µs.
  4. The chip pulls ahead only on large dense systems.Measured at d = 256: from 1.3× slower to 2× faster than the CPU. Extrapolated to d ≥ 1024: 1.3–5× faster than one core.
  5. IR survives imperfect hardware, but 1% mismatch makes κ ≈ 1000 problems physically unstable.At 10% coupling mismatch, plain thermox is 30–290% off. IR still reaches the target.

How the solvers work

On its own, the chip gets accurate very slowly. Wrap it in a cheap digital check-and-correct loop and it gets accurate fast.

The common task

Every problem here is a linear system: find x in A·x = b. Both A and b are known. A is square, symmetric and positive definite.

Robots solve thousands of these a second. A Kalman filter uses one to weigh a camera reading against a prediction. Inverse kinematics uses one to turn a desired hand motion into joint motions. Model predictive control uses one to plan torques a fraction of a second ahead.

Two numbers say how hard a system is. The size d is the number of unknowns. The condition number κ says how unequal the matrix's eigenvalues are: κ = 1 is trivial, κ = 10,000 is hard. On a thermodynamic chip κ matters most, because the system's slowest direction relaxes κ times slower than its fastest.

How a thermodynamic chip solves A·x = b

The chip is d coupled analog cells. In Normal Computing's prototype, that's 8 RLC circuits on a circuit board. You program the couplings so the cells' voltages get pulled toward the solution x*. Meanwhile, heat noise keeps kicking them around.

So the voltages never settle. They wander around x*, and the time average of the readings is your estimate. thermox simulates exactly this: an Ornstein–Uhlenbeck process.

Two things limit how good that average gets:

  • Start-up bias. The chip starts at x₀ = 0, so the early readings drag the average toward zero.
  • Slow averaging. Noise averages out like 1/√time. Ten times more accuracy costs 100 times more chip time.

Iterative refinement: check the answer, then solve only for the mistake

The chip's error is a fixed fraction ε of whatever you ask it to solve. So iterative refinement (IR) only ever asks it for the part that's still wrong:

  1. The digital computer checks the current answer exactly: r = b − A·x.
  2. It scales that leftover r up to the chip's full input range.
  3. The chip solves for the missing piece d.
  4. The computer adds it: x ← x + d.

Each round multiplies the remaining error by ε. With ε = 0.5, that's 50% → 25% → 12.5%. Accuracy improves geometrically with rounds, not like 1/√time.

IR cold starts from zero. IR warm starts from the robot's previous answer. The robot solves a slightly different system every few milliseconds, so with a warm start the first leftover is already tiny.

The digital baselines

  • Exact (Cholesky) factorises the matrix and solves directly, in about d³/3 operations. It's the reference answer.
  • CG (conjugate gradient) is the standard iterative method. Each step is one matrix–vector product (about 2d² operations), the same digital cost as one IR round. We also tried Jacobi-preconditioned CG (PCG), cold and warm, and report the best.

Rules that keep the comparison fair

  • Same targets. Relative error 1e-2, 1e-4 and 1e-6 against numpy's exact answer. A configuration counts only if at least 95% of its solves reach the target.
  • Chip time in samples. One sample is the chip's fastest relaxation time. The matrix is scaled so its largest eigenvalue maps to that speed.
  • Full converter range. Each input is scaled so its largest entry uses its converter's full range, because every cell has its own converter.
  • Best configuration for every method. IR: N from 10 to 1,000 samples per round, with or without Jacobi scaling, cold or warm. CG: plain or Jacobi, cold or warm.
  • Equal chip time in every comparison picture. Plain thermox gets exactly as many samples as IR used. Each picture shows the same chip time spent two ways.

For wall-clock time we model one x86 CPU core and three chip scenarios. The core runs at about 1 GFLOP/s on tiny matrices and 20 GFLOP/s at d = 256.

Robot perception · P1–P3

The Kalman filter in the pick-and-place robot

On all three cameras IR warm matches the exact filter, and the CPU is still faster.

A Franka Panda arm picks a 4 cm cube off a conveyor moving at 8 cm/s. A simulated camera reports the cube's position 33 times a second, with about 1.5 cm of noise. A Kalman filter blends those readings with a constant-velocity model to estimate where the cube is and how fast it's going. The arm aims for where the cube will be.

Every camera frame, the filter solves S·Kᵀ = H·P for its gain K. The gain decides how much to trust each new reading. S = H·P·Hᵀ + R is 3×3, built from the filter's uncertainty P and the camera noise R. There are 6 right-hand sides.

The problem

The camera is equally noisy in every direction, so the filter is equally unsure in x, y and z. That makes S a number times the identity: κ = 1, the easiest system there is. It's the system from the original pick-and-place test.

What happened

IR warm gives a filter you can't tell apart from the exact one. It starts from the previous gain and spends 39 chip samples as 3.9 rounds of 10, landing within 0.006% of the exact gain.

With the same 39 samples, plain thermox gets the gain wrong by 27% on average. The filter shrugs that off for position: 7.6 mm error versus 6.7 mm exact. Velocity suffers more: 17.6 versus 14.7 mm/s.

CG needs under one iteration on average, because a scaled identity takes one step.

The problem

Ten times more noise along the viewing ray pushes κ to about 94. On the chip, the slowest direction of S now relaxes 94× slower than the fastest. So each IR round needs about 100 samples before it reliably shrinks the error.

This is the worst robot problem for the optimistic chip: 224× slower than a CPU solve.

Robot motion · P4–P6

Moving the arm: inverse kinematics and model predictive control

IK hardly needs an accurate solve, MPC works with IR, and the low-weight MPC (P6) is the one problem the chip never solved.

The problem

A hundred times a second, the controller turns the desired gripper pose into joint angles. It uses damped least squares and repeats the step 4 times per tick:

Δq = Jᵀ (J·Jᵀ + λ²I)⁻¹ e

J is the arm's 6×7 Jacobian and e is the 6-D position and orientation error. The 6×6 system changes every tick. It gets harder near awkward poses: κ ≈ 90, up to 144.

The benchmark uses the first of the 4 steps per tick. The robot run below puts the chip in all of them.

What happened

IK is the most forgiving problem in the set. It doesn't need an accurate linear solve at all.

We ran the whole pick-and-place with only the IK solve swapped out; the Kalman filter stayed exact. At 572 samples per solve, plain thermox is 7.6% off every time. The 4 IK steps per tick correct it anyway. The final pose is within 0.23 µm instead of 0.015 µm, and all three robots grasp the cube the same way (9.41 mm, picked).

IR warm still reaches 1e-4, with 19 rounds of 30 samples. CG needs 6 iterations, as you'd expect for a 6×6 system.

The problem

Every tick, model predictive control plans joint torques 0.2 s ahead: 10 steps of 20 ms, using the arm's mass matrix M(q) at its current pose. It applies the first step and replans on the next tick.

The plan is the solution of a 70×70 system H·U = −g, for 7 joints × 10 steps of torque. A weight on torque effort sets the conditioning. Here it's 0.01, which gives κ ≈ 1,500.

What happened

IR warm matches the exact plan, but it takes 29 rounds of 1,000 samples. CG gets there in 26 iterations.

With the same 29,221 samples per plan, plain thermox's torque plans are about 200% wrong. The first torque, the one the arm actually applies, is off by up to 5 N·m.

The problem

Same controller, with a torque weight 10× smaller (0.001). The robot can now spend more torque to track tightly. The system gets 10× harder: κ ≈ 15,000. Low input weights like this are common in practice.

What happened

This is the one problem the chip couldn't solve.

Making it work would take more than 15,000 samples per round, or a preconditioner that tames κ before the matrix goes on the chip.

Physics simulation · P7–P8

A heated plate: the friendliest case for analog hardware

This is the chip's best real-world case: on the 16×16 grid it comes within 2.7× of the CPU.

A heat source moves across a square plate on an n×n grid. We step the temperature forward with implicit Euler: (I + αL)·uk+1 = uk + fk. L links each cell to its four neighbours.

Why it suits the chip: the matrix never changes. You program the chip once, and each time step only sends a new right-hand side. That removes the reprogramming cost that hurts the robot problems. Each step also starts close to the previous temperature field, which is exactly what warm start wants.

Random dense matrices · P9–P17

Separating size from difficulty

Chip time depends on κ, not on d, and the chip beats the CPU only once (P16).

Nine synthetic problems cover every mix of size d = 16, 64 or 256 and difficulty κ = 10, 100 or 1000. Eigenvalues are spread evenly on a log scale from 1 to κ. Eigenvectors are random, so every matrix entry is non-zero. Each problem has 5 independent systems, so warm start doesn't apply and IR here means IR cold.

The pattern across all nine:

  • At equal chip time, plain thermox is 4–19% off.
  • IR reaches 1e-4 in 16–34 rounds.
  • The chip time IR needs grows about 10× for every 10× in κ, and hardly at all with d.
  • CG iterations grow with √κ, and are capped near d for the small matrices.

Results across all problems

Physical practicality

IR copes with imperfect parts, but today's parts aren't precise enough for the hard problems.

The emulated chip is perfect apart from heat noise. Real analog parts aren't, so the benchmark adds two kinds of imperfection.

Coupling mismatch is a fixed random error on every programmed matrix entry, the kind component tolerances cause. Low-precision converters round inputs, outputs and couplings to 6–12 bits.

Rule of thumb from the stability failures: coupling precision has to be finer than about 1/κ. So a κ = 1000 problem needs couplings accurate to better than 0.1%.

Today's parts are far coarser. Normal Computing's prototype has 4 diagonal capacitor values and 3 coupling values (−, 0, +). IBM's 2023 analog chip uses 8-bit inputs and outputs.

RequirementStatus
Each chip solve less than 100% wrong, so IR convergesMet in emulation for κ up to about 1000, with about κ samples per round
Reprogram the matrix every control tickThe main cost for robotics: d² entries per tick. For d ≤ 70 this alone takes longer than a whole CPU solve
One computer↔chip round trip per IR round4–35 per solve. That needs on-chip converters (about 100 ns), not a circuit board on a USB link (about 50 µs)
Coupling precision finer than 1/κNot available today for κ ≳ 100. Ill-conditioned robot problems such as MPC need preconditioning first
Large all-to-all arrays (d ≥ 1000)Needed for any speed advantage: about a million programmable couplings at d = 1024. Analog memory chips reach 64 × 256² cells at 8 bits, but no thermodynamic solver that size exists

Conclusion

Can a thermodynamic chip help a robot? Not yet. IR makes the chip accurate, but one CPU core is still faster on every robot-sized problem.

The method works. IR turns the chip from a slow, noisy averager into a solver that gains a fixed factor of accuracy every round. It reached 1e-4 on 16 of 17 problems, with 10⁵–10⁷× less chip time than plain thermox. It also absorbs the coupling mismatch and coarse converters that real analog hardware has.

For a robot, the chip isn't practical today. Robot linear algebra is small: a 3×3 Kalman gain, a 6×6 IK step, a 70×70 MPC plan. One CPU core solves these in 0.3–10 µs.

An analog chip has to be loaded with the new matrix, wait for its slowest mode to relax, and swap data with the computer several times per solve. Even an optimistic future chip needs 4–330 µs for all that.

Some robot tasks barely need accuracy anyway. IK picked the cube with a solver that was 7.6% wrong, and the Kalman filter tolerated 30–44% gain errors.

Where it could matter. Large dense systems, with d of 1,000 or more and moderate conditioning. The chip would need fast on-chip converters and couplings precise to better than 1/κ.

In that regime the chip acts like a strong preconditioner. At d = 256, IR needed 2.5–7× fewer digital steps than CG once κ ≥ 100. Nobody has built that chip yet. If someone does, IR warm is the right way to drive it.

Next experiments: precondition the MPC before it goes on the chip, test d ≥ 1000 directly, and add output-voltage limits and drift to the emulator.

Reproduce & sources

Code, results and the sources for this page are all in the GitHub repository pratik-ingle/thermox-robot-bench. ./setup.sh installs the dependencies and fetches the Panda model from MuJoCo Menagerie. On headless Linux, set MUJOCO_GL=egl first. Then run:

git clone https://github.com/pratik-ingle/thermox-robot-bench.git && cd thermox-robot-bench && ./setup.sh

python thermo_benchmark.py --problem all && python thermo_benchmark.py --report

python report/make_assets.py --part method,kf,ik,mpc,heat,rand,tables,results && python report/assemble.py

The last command rebuilds this page in docs/, which GitHub Pages serves.

  • Wall-clock times are modelled, not measured. The parameters are in Part 1. Everything beyond d = 256 is extrapolated.
  • Oracle stopping. CG and IR both stop on the true error. A real controller would have to stop on the residual.
  • Original robot test. The P1 pick-and-place video comes from the earlier test, which scaled inputs by their total length instead of per converter.
  • Emulator limits. thermox models no output voltage limit, parasitic dynamics or drift. Real devices would do worse.
